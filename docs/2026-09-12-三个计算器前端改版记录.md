## 2. 目标与已经确认的取舍

原界面在手机上存在横向拥挤、表格和说明难浏览、文字与按钮不够舒适等问题；PC 上部分控件与数值散得过开。本轮目标是改善阅读、定位和操作，保留原有游戏使用规律。

| 决定 | 原因及最终状态 |
| --- | --- |
| 白底界面 | 用户明确不希望采用暗底；最终使用白色卡片、浅灰蓝背景、蓝色主操作 |
| 保留业务顺序 | 用户已按游戏规律安排按钮与字段；士兵通常先攻击，因此不随意把英雄放到前面 |
| 白字小数保留 | 用户认为精确白字有必要；保留小数显示，最后统一展示上限为两位 |
| 全局额外加粗回退 | 中途尝试整体加粗，用户认为过重，已回退；之后只补强红/橙色数字等必要强调 |
| 长说明可折叠 | 使用说明一整块默认收起，阅读时再展开 |
| 士兵结果以士兵为主体 | 当前士兵名称、形象和属性突出显示，搭配英雄作为辅助信息 |
| 英雄属性位置按游戏 | 头像与生命在左；右侧“攻击/智力”“防御/魔防”“技巧/空位”，PC 与手机对应一致 |
| 数字最多两位小数 | 仅限制显示，不补零、不删原公式、不把显示舍入带入后续运算 |
| 本地只读联调 | 使用朋友授权的数据读取接口验证前端，不改数据库、不改后端 |

标题与主要结果仍保留必要强调。“回退整体加粗”不是把所有标题、按钮和结果都强行设为同一字重。装备特效、羁绊等长段说明保持普通阅读色和适当字重，避免大片高饱和色文字。

## 3. 三页共同变化

### 3.1 页面外框、导航与样式范围

- 为三个计算器添加 `calculator-layout` / `calculator-page` 范围，在公开计算器中使用顶部品牌与三个页面入口。
- 计算器页面隐藏原侧边管理导航及登录、账号、Agent 等入口。中途预览曾有“全部功能”按钮，按用户意见移除。
- 非计算器页面保留原管理导航、登录、账号与 Agent 逻辑；没有删除这些功能。
- 保留现有页脚备案链接，增加底部留白，给快捷操作栏留出空间。
- 样式限定在计算器范围；Element Plus 挂到 `body` 的弹窗、下拉选项等，通过当前计算器状态获得一致主题。

### 3.2 视觉与布局

- 统一中文无衬线字体回退、正文颜色、字号、行高、标题层级、表单标签、输入框和按钮尺寸。
- 蓝色用于主要操作；次要操作使用浅底/描边；重置降低视觉抢占，红/橙色保留给必要的数值与状态强调。
- 改善标签换行、复选框长文案、百分号附加区、禁用输入的对比度、下拉选项和缓存弹窗的阅读体验。
- 统一卡片留白、圆角、分隔线与结果分组，减少无意义的大空白。
- 页面主体最大宽度约 1160px；PC 结果正文最大 880px，面板部分表单输入最大 260px，单点/AOE 部分输入最大 280px。
- 神契筛选表单最大 560px；701–1000px 范围的白字区使用双列，英雄选择区最大 420px。具体断点以 CSS 为准。
- 常用触控控件约 44px 或以上；手机上按空间调整换行，横向滚动主要留给确实需要多列对照的表格。

主要主题色包括主蓝 `#245dcc`、正文 `#253143` / `#3e4d62`、辅助文字 `#607086`、绿 `#197454`、橙 `#966314`、红 `#ba3943`。它们是当前实现基线，不是要求所有元素使用同一个颜色或字重。

### 3.3 参考资料与使用说明

- 抽出 `calculator-reference.vue`，统一神契晨曦之祝、士兵科技、AOE 士兵科技、职业克制等参考弹窗。
- 弹窗增加清楚的标题、说明、关闭/返回入口，限制高度并在内容区滚动。
- 手机上的科技/特效目录按分组卡片阅读；职业克制仍用对照矩阵，保留固定首列和横向浏览，正负系数做视觉区分。
- 参考按钮去掉重复的“点击打开查看”等前缀。
- 抽出 `calculator-guide.vue`，三个计算器的使用说明整体默认折叠；说明展开后使用段落、分组或列表，保留原业务解释和归属说明。

### 3.4 页面目录、结果跳转与设置折叠

- 新增固定快捷栏：`页面目录`、`查看结果`。
- 目录按页面现有区域顺序列出可见区块，结果区作区分；不改变页面字段顺序。
- 查看结果后可以 `返回修改位置`，回到跳转前的滚动位置；目录也提供返回顶部。
- 通过目录进入已收起的设置区时自动展开；进入使用说明时展开说明。
- 手机输入框正在编辑时隐藏快捷栏，减少与输入区域争抢空间；为系统减少动画偏好提供直接滚动。
- 面板中的英雄白字、神契设置、装备与绿字加成区可手动收起，默认仍展开。收起显示摘要，内容使用 `v-show` 保留，不清空参数。

### 3.5 公式输入反馈

- 原 `mz-input` / `mz-percent-input` 改为共用 `calculator-formula-input.vue`，保留其调用方式及原始输入缓存键。
- 继续支持数字、正负号、`+ - * /` 和括号；百分比仍按原单位输入，例如 `20+5+8` 表示 33%。
- 有效公式显示结果预览；未完成、括号错误、除零等分别提示。
- 输入未完成或无效时保留该字段上次有效数值，结果区提示存在待完善公式；不把错误输入直接变成 0。
- 提供数字/公式键盘切换和运算符按钮；保留键盘 Tab / Enter 操作。
- 自动关联与禁用状态仍随原开关变化，禁用或只读的计算值只格式化显示。

### 3.6 最多两位小数

统一出口为 `src/common/calculator-display.mjs`，使用 big.js 四舍五入，去掉不必要的尾零。

| 原显示 | 当前显示 |
| --- | --- |
| `3807.692307…` | `3807.69` |
| `258923.076923…` | `258923.08` |
| `336599.999999…` | `336600` |
| `80` | `80` |
| `1.3` | `1.3` |
| 比例 `0.123456` 的百分比 | `12.35%` |
| 血量 `12.3456/100.6789` | `12.35/100.68` |

覆盖公式预览、攻防关系表、AOE 分项与保存明细、护盾/血量、面板加成、属性输出、只读公式框和禁用的计算数字框。原来已按游戏规则显示整数或一位小数的结果继续保留；白字输入原有的两位小数显示保留。

编辑中的原公式和手动数值不截断。`1/3` 的预览可显示 `0.33`，计算仍使用原求值结果。`formatCalculatorResult` 对“剩余/最大血量”分别格式化两端，不把它当除法求值。静态参考表原已有的整数/短小数无需再次重写。

## 4. 单点计算器的具体变化

- 攻方、守方输入区沿用士兵/英雄原排列，改进不同屏幕的布局、控件和参考入口。
- 将“战斗攻防差与增减伤关系”标题缩短，保留“已考虑克制系数、无视防御和地形修正”的说明。
- 此表的攻防差、各类增减伤、技能倍率、单段、暴伤倍率与暴击单段通过显示格式化，消除长小数挤到第二行的情况。
- “关联单段伤害计算结果”“存在动画造成的段数丢失”等标签缩短，原含义移到辅助说明中，绑定条件未变。
- 为最终结果增加明确标题、分组和主要伤害强调；血量、护盾、段数等结果也纳入显示格式化。
- 整页重置前明确提示将重置攻守方参数、血量与段数；取消保留数据。
- 增加攻方、守方、单段伤害、段数/血量、最终结果、说明等目录锚点。
- 原伤害计算、克制、动画丢段、段数分配和血量模拟逻辑保留。

## 5. AOE 计算器的具体变化

- “实际 AOE 伤害”和“总伤害”均改为有图标、较大标题、分项和主要合计的结果卡片，避免只有上方醒目。
- 英雄打英雄、英雄打兵分别显示，合计突出；护盾承伤、剩余护盾和战后固伤仍有对应位置。
- 当前段标明“尚未计入合计”或“已保存为第 N 段”。保存按钮按状态显示 `保存并计入合计` / `再次保存一段`，相同参数仍允许继续新增一段。
- 保存成功有反馈，增加短暂防连点；有无效公式或护盾设置冲突时阻止保存并说明原因。
- 已存记录默认展示段号、该段总伤害与删除入口，分项通过 `查看分项` 展开；合计处减少重复堆列。
- 提供 `清空已存段数`，确认后只清保存记录，保留当前攻守方、护盾等输入；取消保留记录。
- 护盾变化后提醒恢复原护盾值，或清空旧段再保存。该提示是现有计算前提的交互保护，没有另改护盾算法。
- 整页重置明确包含攻守方、护盾、固伤和已保存段数；原单段删除确认保留。
- 同步使用说明中的保存/清空表述。原伤害、取整、分段累加和战后固伤计算保留。

## 6. 面板模拟计算器的具体变化

### 6.1 设置与表格

- 英雄白字区改进英雄/职业选择、头像、取整参考值和小数白字的布局；不移除精确白字。
- 神契操作统一为一致的按钮体系，保留“一键点满、重置、导出、导入”的顺序；筛选区在 PC 不再铺得过宽。
- 神契属性表、附魔表增加 `calculator-scroll-table` 外框：有溢出才显示提示与左右按钮，根据列宽移动；边界按钮禁用，保留固定首列及清晰的滚动反馈。
- 装备选择、装备头像与效果说明、附魔/职业精通/铸纹/神契/圣镜/绿字统计等统一排版，改善长文字和加成数字的对齐。
- 对铸纹区错误沿用的职业精通标签作修正；部分关联开关改成短标签加辅助说明。
- 神契晨曦之祝重置和附魔列重置增加作用范围清楚的确认；整页重置说明独立神契设置和已存缓存会保留。
- 原缓存与导入/导出功能保留，已有缓存弹窗做了手机视觉适配，没有重做缓存数据结构或管理流程。

### 6.2 英雄与士兵结果

- 英雄结果用 CSS 网格对应游戏位置：左侧头像及生命，右侧攻击/智力、防御/魔防、技巧/空位。
- PC 英雄结果网格最大约 640px，头像约 96px；手机头像约 64px，并调整身份区、标签和结果间距，避免拥挤。更窄屏幕继续使用现有断点调整。
- 士兵结果增加 `当前士兵` 和 `搭配英雄` 的明确区分，士兵名称与形象更突出。
- 士兵各项属性将基础值、加成、百分比与最终结果分层展示，保留“不考虑克制/考虑克制”与原公式。
- 优化装备说明、英雄羁绊、士兵技能等长文案的行高和阅读色，避免所有说明都使用刺眼的橙/红色。
